# 보고: 매대 테스트를 앱에 붙이는 계획

2026-11-23 · 승인 요청

## 1. 결론

오늘 안에 **"컨셉을 매대에 올리면 가상 손님 300명이 고르고, 결과가 한 장으로 나오는"** 데까지 앱에 붙입니다. 약 4시간이 걸립니다. 손님이 걸어 다니는 모습, 한 손님에게 묻기, 개선안 테스트는 오늘 하지 않고 현장에서 붙입니다.

승인하시면 바로 시작합니다. 정해 주실 것은 맨 아래 6절의 두 가지입니다.

## 2. 지금 상태

| 구분 | 상태 |
|---|---|
| 1부 컨셉 만들기 | 끝까지 됩니다. 확정한 컨셉을 제안서로 내려받을 수 있습니다. |
| 입체 매장 | `/store`에 멈춰 있는 매장이 있습니다. 음료 55개와 신제품 자리가 보입니다. |
| 매대 테스트의 방법 | 터미널에서 직접 돌려 확인했습니다(아래). 앱에는 아직 붙어 있지 않습니다. |
| "매대에 올려 보기" 버튼 | 누르면 "아직 준비 중이에요"라고 답합니다. |

터미널에서 확인한 것

- 새 제품 한 줄을 매대 55개 옆에 넣고 가상 손님에게 물으면, **약한 컨셉과 좋은 제품이 갈립니다.**
  - 아침용 유자생강 제로: 484명 가운데 0명이 집음
  - 오이오차 녹차(실제로 잘 팔리는 제품): 20대 100명 가운데 4명, 매대 56개 가운데 9번째
- 집은 손님이 전에 무엇을 집던 사람인지, 안 집은 손님은 무엇이 걸렸는지도 함께 나옵니다.
- 100명에 3분, 300명에 9분이 걸립니다.

즉 **방법은 확인됐고, 남은 일은 이것을 앱의 화면과 칠성이의 대화에 잇는 것**입니다.

## 3. 만들 것

기획자가 겪는 순서대로 적습니다.

### 3-1. 시작하기

- 1부에서 컨셉을 확정한 뒤 **"매대에 올려 보기"**를 누릅니다.
- 칠성이가 누구에게 물을지 한 번 확인합니다.

> 20대 손님 300명에게 물어볼게요. 절반은 저녁 식사 자리, 절반은 20대가 평소 음료를 마시는 자리예요. 시작할까요?

- "시작하기"를 누르면 테스트가 돕니다.

### 3-2. 기다리는 동안

- 오른쪽 작업대에 입체 매장이 뜨고, 신제품 자리에 내 컨셉이 놓입니다.
- "다녀간 손님 37 / 300"처럼 숫자가 올라갑니다.
- **100명이 넘으면 "먼저 온 결과 보기"가 열립니다.** 눌러도 뒤에서는 300명까지 계속 돕니다.
- 다 끝나면 칠성이가 알려 줍니다.

### 3-3. 결과 한 장

아래는 모양을 보이기 위한 예시입니다(숫자는 오이오차 녹차를 돌린 실제 값).

```
20대 손님 100명에게 물었어요
────────────────────────────────────────────
집은 손님            4명
매대에서의 순위       56개 가운데 9번째
                    8번째 트레비 레몬 4명 · 10번째 스타벅스 카페라떼 3명

집은 손님이 전에 집던 것
  자사 제품 3명      더하다 보리차, 칠성사이다 제로, 트레비
  경쟁사 제품 1명     코카콜라

안 집은 손님이 걸린 점
  늘 마시는 것이 있음            55명
  처음 보는 제품이라 망설여짐      38명
  지금 상황에 안 맞음             30명
  맛이 끌리지 않음                25명
  가격이 비쌈                     9명

손님의 말
  집은 손님     "밥이랑 같이 마실 거니까 달지 않고 깔끔한 녹차가 좋겠네요."
  안 집은 손님   "녹차는 쌉쌀하고 밍밍해서, 그 돈이면 탄산 마실래요."
```

이 한 장이 답하는 것

| 기획자의 물음 | 카드에서 답하는 곳 |
|---|---|
| 팔리나? | 집은 손님 수, 매대에서의 순위 |
| 누구 것을 가져오나? | 집은 손님이 전에 집던 것 |
| 왜 안 집나? | 걸린 점의 순서, 손님의 말 |
| 누구에게 물은 결과인가? | 맨 위 한 줄 |

### 3-4. 뒤에서 도는 부분

- 테스트는 대화와 따로 뒤에서 돕니다. 기다리는 동안 칠성이와 계속 이야기할 수 있습니다.
- 답은 올 때마다 저장합니다. 서버를 껐다 켜도 이어서 돕니다.
- **같은 컨셉을 다시 올리면 저장된 결과가 바로 뜹니다.** 시연에서 9분을 기다리지 않기 위한 장치이기도 합니다.
- 손님이 받는 글은 사전 측정에서 검증한 것을 그대로 씁니다. 바꾸지 않습니다.
- 모델을 부르는 곳은 한 곳이라, 현장에서 API나 다른 모델을 받으면 그곳만 바꿉니다.

## 4. 일정 (오늘)

| 순서 | 일 | 걸리는 시간 |
|---|---|---|
| 1 | 테스트를 돌리고 결과를 모으는 서버 부분 | 1시간 반 |
| 2 | 화면의 카드 두 장(기다림, 결과) | 1시간 반 |
| 3 | 칠성이의 대화와 잇기 | 1시간 |
| 4 | 시연할 컨셉을 300명으로 미리 돌려 저장 | 뒤에서 컨셉마다 9분 |

구현은 지금까지처럼 Opus에게 맡기고, 제가 검토하고 직접 눌러 본 뒤 커밋합니다.

## 5. 오늘 하지 않는 것

| 하지 않는 것 | 이유 | 언제 |
|---|---|---|
| 손님이 매장을 걸어 다니는 모습 | 보기 좋지만 결과에는 영향이 없음 | 현장에서 시간이 남으면 |
| 한 손님을 불러 묻기 | 결과 카드가 먼저 있어야 함 | 현장 |
| 개선안 테스트(가격·용량을 바꿔 다시) | 같은 장치를 한 번 더 쓰는 것이라 뒤에 붙이기 쉬움 | 현장 |
| 결과 보고서 | 제안서의 "향후 계획" 칸을 결과로 바꾸는 방식으로 | 현장 |
| 전체 손님 100명 참고 | 타깃 손님만으로 판단할 수 있음 | 필요하면 |
| 비용을 줄이는 작업 | API를 받아야 잴 수 있음 | API를 받은 뒤 |

## 6. 위험과 정해 주실 것

**위험**

- **시연할 컨셉이 아직 없습니다.** 유자생강 제로는 0명이라 결과 화면이 비어 보입니다. 1부에서 만든 컨셉 가운데 집히는 것이 나올 때까지 몇 개를 돌려 봐야 합니다.
- **새로 돌리면 9분입니다.** 발표 시간 안에 처음부터 끝까지 새로 돌리는 것은 어렵습니다.
- **100명에 4명 같은 숫자는 흔들립니다.** 다시 돌리면 1명에서 10명 사이로 움직일 수 있어, 카드에 그 폭을 함께 그립니다.

**정해 주실 것**

1. **시연할 컨셉을 제가 골라도 될까요?** 서버 부분이 되는 대로 1부에서 컨셉 두세 개(예: 저녁 식사에 곁들이는 제로 콜라)를 만들어 돌려 보고, 가장 잘 나온 것을 권하겠습니다.
2. **시연은 미리 돌려 둔 결과로 할까요?** 새로 돌리기 시작하는 모습은 앞부분만 보여 주고, 결과는 저장된 것을 여는 방식을 권합니다. 화면에는 언제 몇 명으로 돌린 결과인지 적습니다.

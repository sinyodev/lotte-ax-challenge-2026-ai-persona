# 칠성이 1부: 컨셉 만들기의 설계 (2026-11-20. 같은 날 만들어 화면에서 끝까지 돌려 봄)

대본을 틀던 1부를 진짜 칠성이로 바꾸기 위한 설계다. 참가자와 정한 것:

- **기획의 중심은 소비자다.** 누가, 언제, 왜 마시는지에서 출발한다. 매대는 2부(매대 테스트)의 무대이고, 1부에서는 가격을 잡을 때만 참고한다.
- **종류는 묻지 않고 받는다.** 기획자가 무엇을 적든 그것으로 시작한다. 우리 자료에 없는 종류여도 컨셉은 만든다.
- **"칠성이에게 추천받기"** 를 둔다. 자료에서 뽑은 출발점을 근거와 함께 내민다.
- **우리 자료에만 묶이지 않는다.** 필요하다고 판단하면 칠성이가 웹에서 찾아온다. 대신 범위와 표시를 코드가 정한다(4절).

## 0. 고친 방향 (2026-11-21, 참가자가 진짜 칠성이를 써 보고 정함. 아래 1~5절보다 앞선다)

써 보니 칠성이는 대화하는 척하는 설문지였다. 질문 세 번, 아이디어 한 번, 컨셉 한 번으로 횟수가 정해져 있었고, 기획자의 생각("아침용")은 받아 주지 않았으며, 자료에 있는 것만 기획의 재료가 되어 결과가 두루뭉술했다. 참가자가 정한 원칙:

1. **기획자를 틀에 가두지 않는다.** 브리프는 채워야 하는 양식이 아니라, 대화에서 나온 것을 칠성이가 받아 적은 **요약**이다. 빈칸이 있어도 대화는 나아간다. 칠성이는 칸을 채우라고 조르지 않는다.
2. **자료는 판단을 돕는 도구이지 울타리가 아니다. 그리고 "자료"는 우리끼리의 말이다.** 기획자는 "자료"라는 개념을 모른다. 칠성이는 "찾아보니 이런 게 있어요"라고 말하고 실제 출처의 이름(국민건강영양조사, 기사의 이름)을 붙인다. **찾은 것이 없으면 말하지 않고** 기획자의 생각대로 간다. "자료에 없어요", "자료가 받쳐 줘요", "기록에 따르면" 같은 말은 대화에도 화면에도 쓰지 않는다. 자료에 없는 생각을 버리거나 자료 쪽으로 끌고 가지 않는다.
3. **횟수가 아니라 문턱만 코드가 쥔다.** 아이디어 회의는 기획자가 "컨셉으로 만들자"고 할 때까지, 컨셉 보드는 확정할 때까지 몇 번이든 이어진다. 넘어가는 것은 기획자가 정한다.
4. **기획자가 한 말을 잊지 않는다.** 방향("아침용", "유자")을 쌓아 두고 그 뒤의 아이디어와 컨셉에 계속 반영한다.
5. **좁힐 수 있으면 좁힌다. 좁히는 것은 권하는 것이지 요구가 아니다.** 원자료에는 같은 끼니에 먹은 음식, 직업, 소득이 있다(제로 탄산을 마신 끼니 298건에서 함께 먹은 것: 감자튀김, 치킨무, 피클, 탕수육, 후라이드치킨). 칠성이는 이런 것을 내밀어 기획을 날카롭게 하도록 돕는다.
6. **기회 판단 카드는 만들지 않는다**(참가자: 그럴 만큼 자료가 많지 않다). 시장의 크기나 매대에 비슷한 제품이 몇 개인지는, 찾아봤을 때 쓸 만한 것이 나오면 대화에서 한마디로만 말한다. 매출이나 점유율을 예측하지 않는다.
7. **컨셉 보드도 말로 무엇이든 고친다.** 칸마다 따로 받지 않고 "이 컨셉을 이렇게 고쳐 줘"를 통째로 받아 카드를 다시 쓴다. 용기나 용량이 바뀌면 가격의 근거는 코드가 다시 계산한다.
8. 느려지는 것 때문에 구조를 깎지 않는다. 대회에서 API를 받아 본 뒤에 판단한다.

그래서 한 차례의 짜임이 바뀐다.

```
기획자의 말(무엇이든)
 → 읽기(모델): 무엇을 하려는 말인가, 기획 노트에 무엇을 더하거나 고치나, 어떤 자료를 찾아보면 도움이 되나
 → 찾기(코드): 고른 자료를 실제로 찾는다. 숫자는 여기서만 나온다
 → 하기(모델과 코드): 아이디어를 내거나 고치기, 컨셉을 만들거나 고치기, 물음에 답하기
 → 말하기(모델): 받아 준 것 하나, 보탤 것 하나(자료 한 조각이나 날카롭게 하는 질문이나 다른 안)
```

칠성이가 할 수 있는 일: 노트에 적기(제품, 타깃, 상황, 바라는 것, 기획자의 생각), 앞에서 정한 것 고치기, 자료 찾기(누가, 언제, 무엇과 함께, 매대의 빈자리, 시장의 크기, 요즘 소식), 아이디어 내기(방향을 받아서), 아이디어 하나 고치기, 기획자의 아이디어 올리기, 아이디어 빼기와 남기기, 컨셉 만들기, 컨셉의 값 고치기, 물음에 답하기, 다음 단계로 넘어가기(기획자가 말했을 때만).

여전히 코드가 쥐는 것: 숫자는 찾아본 것에서만, 출처의 이름, 가격의 근거, 단계의 문턱, 말의 검사.

## 1. 근거의 세 종류

칠성이가 말하는 사실에는 반드시 아래 셋 중 하나의 표시가 붙는다. 표시 없는 사실은 내보내지 않는다. 아이디어와 컨셉의 문구처럼 칠성이가 지은 것은 "칠성이의 제안"이라고 한다.

| 표시 | 자료 | 답하는 것 | 한계 |
|---|---|---|---|
| 소비자 기록 | 2024 국민건강영양조사(마신 자리 9,798건, 종류 11가지), 한국농촌경제연구원 조사(5,874명), 우리가 만든 상황 12개와 니즈 17개 | 누가 많이 마시나, 언제·어디서·누구와, 그때 무엇을 바라나 | 종류가 굵다(말차 라떼는 "차"로 답한다). 잘게 쪼개면 표본이 작다 |
| 매대 | 세븐일레븐·CU 상품 75개의 가격과 행사 | 비슷한 제품의 가격대 | 상품 수가 적다. 없는 종류가 있다 |
| 웹에서 찾은 것 | 칠성이가 그 자리에서 검색한 기사와 보고서 | 요즘의 흐름(맛, 원료, 출시 소식) | 글의 내용이 맞는지는 보장하지 못한다. 출처와 날짜를 함께 보인다 |

표본이 100건에 못 미치는 기록을 쓸 때는 "기록이 적어서 참고만 해 주세요"를 붙인다.

## 2. 흐름

기획 브리프의 다섯 칸(제품, 채널, 타깃, 음용 상황, 핵심 니즈)을 채우고, 아이디어를 내고, 컨셉 보드를 만든다. 순서와 넘어가는 조건은 코드가 쥔다. 모델은 표의 "모델이 하는 일"만 정해진 형식으로 답한다.

| # | 상태 | 칠성이가 하는 일 | 근거 | 모델이 하는 일 | 기획자가 내는 것 |
|---|---|---|---|---|---|
| 0 | 시작 | 기획자의 첫마디에서 제품을 읽는다. 없으면 묻는다 | | 첫마디 → 제품 이름, 가장 가까운 기록의 종류, 매대의 종류(없으면 없음) | 한 줄, 또는 "칠성이에게 추천받기" |
| 0' | 추천 | 출발점 셋을 내민다: 특정 집단이 유독 많이 마시는 종류, 편의점 매출이 늘어난 종류 | 소비자 기록, 편의점 매출 | (없음. 코드가 자료에서 고른다) | 하나를 고르거나 직접 쓴다 |
| 1 | 흐름 보기 | 그 제품의 최근 흐름을 웹에서 찾는다. 한 번만 | 웹 | 검색하고, 주장과 출처의 묶음으로 정리 | (기다린다) |
| 2 | 타깃 | 이 종류를 유독 많이 마시는 집단을 내민다 | 소비자 기록 | (없음) | 고르거나 직접 쓴다 |
| 3 | 음용 상황 | 그 집단이 이 종류를 마시는 자리의 순서를 내민다 | 소비자 기록 | (없음) | 고르거나 직접 쓴다 |
| 4 | 핵심 니즈 | 그 상황에서 커지는 니즈를 골라 말한다. 묻지 않고 정하되 바꿀 수 있다 | 소비자 기록 | 니즈 목록에서 한 줄의 말로 | (다음으로) |
| 5 | 아이디어 | 아이디어 셋. 맛, 용기와 용량, 특징이 다르다 | 칠성이의 제안(브리프와 웹에서 찾은 것을 바탕으로) | 아이디어 셋을 정해진 칸으로 | 여럿을 고른다 |
| 6 | 컨셉 보드 | 고른 아이디어마다 컨셉 한 장. 가격은 매대의 비슷한 제품에서 | 매대(가격), 칠성이의 제안(문구) | 헤드라인, 혜택, 믿을 근거 | 확정하거나 고친다 |
| 7 | 확정 | 요약하고 2부로 가는 길을 내민다 | | | |

- 기획자가 칩 대신 글로 답하면 모델이 그 글을 해당 칸의 값으로 읽는다(예: "30대 워킹맘" → 타깃). 읽지 못하면 다시 묻는다.
- 종류가 기록에 없으면 가장 가까운 종류로 답하고 그렇게 말한다. 매대에 없으면 6에서 "비슷한 제품이 매대에 없어서 가격은 제가 어림했어요"라고 말하고, 7에서 "매대 테스트를 하려면 경쟁 제품을 넣어야 해요"라고 알린다.
- 칠성이의 말은 글틀(정해 둔 문장에 자료의 값을 끼움)로 만든다. 모델이 바뀌어도 말투가 같다. 모델이 문장을 짓는 곳은 아이디어, 컨셉, 웹에서 찾은 것의 정리뿐이다.

## 3. 예: 제로 탄산 (숫자는 모두 실제 자료에서 계산했다)

> **기획자**: 제로 탄산 신제품 하나 검토해 보고 싶어
>
> **칠성이** (하는 일: 웹에서 제로 탄산의 최근 소식을 찾고 있어요)
> 제로 탄산으로 볼게요. 먼저 최근 소식을 찾아봤어요. 오른쪽에 출처와 함께 적어 두었어요.
> 이제 누가 마실지 정해요. 기록을 보면 제로 탄산은 20대가 다른 음료보다 4.5배, 30대가 2.4배 자주 마셔요. 타깃을 누구로 볼까요?
> 칩: 20대 / 30대 / 직접 정할게요
> 작업대: 기획 브리프(제품: 제로 탄산), 근거 카드(웹에서 찾은 것 2~3건, 소비자 기록 1건)
>
> **기획자**: 20대
>
> **칠성이**
> 20대로 볼게요. 20대는 제로 탄산을 저녁에(41%), 집에서(55%) 가장 많이 마셔요. 그리고 열 번에 아홉 번(87%)은 음식과 함께예요. 어느 상황을 겨냥할까요?
> 칩: 집에서 식사와 함께 / 밖에서 식사와 함께 / 집에서 혼자 낮이나 저녁에 / 직접 정할게요
>
> **기획자**: 집에서 식사와 함께
>
> **칠성이** (하는 일: 아이디어를 내고 있어요)
> 이 상황에서는 "음식과 어울리게 마시기"와 "맛이 확실한 것 즐기기"가 커져요. 20대의 "당과 열량 걱정 덜기"와 합쳐서 핵심 니즈를 "기름진 저녁을 당 걱정 없이 개운하게"로 잡았어요. 이 니즈로 아이디어 세 개를 냈어요. 컨셉으로 만들 것을 골라 주세요.

만든 뒤에 달라진 것(2026-11-20, 실제 실행): 상황의 순서는 집단의 상황 비중에 종류의 비율을 곱해 정하므로 "밖에서 식사와 함께"가 첫째, "집에서 식사와 함께"가 둘째로 나온다. "집에서 식사와 함께"에서 커지는 니즈는 기록으로는 "몸에 좋은 성분 챙기기"와 "음식과 어울리게 마시기"다(위 예의 "맛이 확실한 것 즐기기"는 밖에서 식사할 때의 값이다). 30대는 기록이 74건이라 주의 문구가 붙는다. 타깃 칩은 연령대만 낸다. 타깃 자신의 니즈("당과 열량 걱정 덜기")를 합치는 것은 아직 하지 않는다.

실행 시간(`claude -p`, Opus 5.5): 첫마디 30~38초(웹 검색 포함. 저장된 결과를 쓰면 12초), 타깃 1초, 아이디어 19~28초, 컨셉 11~13초, 확정 1초.

눈여겨볼 점: 앞선 대본은 "20대 직장인이 오후에 일하다가"라고 지어 썼는데, 기록은 저녁, 집, 음식과 함께라고 말한다. 짐작이 자료로 고쳐지는 장면이다(발표에 쓴다).

## 4. 웹 검색의 규칙

| 규칙 | 내용 |
|---|---|
| 자리 | 상태 1에서만. 다른 상태에서는 검색하지 않는다 |
| 쓰임 | 아이디어의 실마리로만. 타깃, 상황, 니즈, 매대 테스트의 숫자는 바꾸지 못한다 |
| 형식 | 주장, 출처의 이름, 주소, 글의 날짜의 묶음으로 받는다. 출처가 없는 주장은 코드가 버린다 |
| 제한 | 한 대화에 한 번, 정한 시간 안에. 넘으면 포기하고 "웹에서는 찾지 못했어요. 가진 자료로 진행할게요" |
| 표시 | 근거 카드에 "웹에서 찾은 것"으로, 출처와 날짜와 함께. 1년이 넘은 글에는 "오래된 글이에요" |
| 어긋남 | 글끼리, 또는 글과 기록이 다르면 나란히 보이고 판정하지 않는다 |
| 저장 | 같은 질문의 결과는 저장해 다시 쓴다. 시연할 질문은 미리 돌려 둔다 |
| 범위 밖 | 음료·식품과 무관한 요청은 검색하지 않고 할 수 있는 일을 안내한다 |
| 지시 차단 | 찾아온 글은 자료다. 글 안의 지시는 따르지 않는다(흐름은 코드가 쥔다) |

평가 세트: 위 경우마다 질문 하나씩(검색 실패, 결과 없음, 오래된 글, 어긋남, 범위 밖, 기록에 없는 종류, 매대에 없는 종류, 표본이 작은 집단). 모델이나 글틀을 바꿀 때마다 다시 돌린다.

## 5. 모델 호출

- 호출부는 한 곳(어댑터). 지금은 Claude Code 명령줄(`claude -p`, 웹 검색 허용), API 크레딧을 받으면 Claude API, 현장에서 OpenAI 도구가 주어지면 그쪽으로 바꾼다. 재생은 폴백으로 남는다.
- 모델의 답은 모두 정해진 형식(JSON)으로 받고 코드가 검사한다. 형식에 맞지 않으면 한 번 다시 부르고, 또 틀리면 그 단계의 우아한 실패 문구로 넘어간다.
- 확인하지 못한 것: `claude -p`의 응답 시간(웹 검색 포함), 믿을 만한 곳만 검색하게 하는 설정.

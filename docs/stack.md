# 기술 스택, 작업 환경, 디자인 시스템

무엇으로 만들고, 누가(어느 모델이) 어떻게 나눠 만들고, 화면의 모양을 무엇으로 통일하는지 정한 문서다. 화면 구조는 [ux.md](ux.md), 문구는 [ux-writing.md](ux-writing.md)에 있다. (2026-11-18 참가자와 정함)

## 1. 스택 (2026-11-19 확정. 임시 폴더에서 후보를 실제로 돌려 보고 정했다)

기존에 연습용으로 만든 입체 예제는 쓰지 않고 이 저장소 안에 새로 짓는다. 지원서에 적은 Streamlit은 쓰지 않는다. 대화 옆의 작업대, 눌러서 오가는 단계, 입체 매장을 한 화면에 만들기 어렵기 때문이다.

| 자리 | 선택 | 이유 |
|---|---|---|
| 화면 | Vite 8 + React 19 + TypeScript, pnpm | 타입 검사와 빌드로 실수를 기계가 잡는다. Next.js는 쓰지 않는다(서버가 파이썬이다) |
| 디자인 시스템과 부품 | **Meta Astryx** (`@astryxdesign/core` 0.7.16, MIT, 베타. 판을 고정한다) | 대화 부품, 단계 표시줄, 카드, 표, 세그먼트 컨트롤, 앱 틀이 한 벌로 있다. 색·글꼴·모서리를 테마 한 곳에서 바꾼다 |
| 배치 | Tailwind 4 (간격과 배치에만) | Astryx와 함께 쓰는 방법이 문서에 있다. shadcn은 쓰지 않는다 |
| 대화 상태 | Vercel AI SDK 7 (`ai`, `@ai-sdk/react`의 `useChat`). 판을 고정한다 | 서버의 스트림을 받아 메시지로 만들어 준다. Astryx의 대화 부품에 우리가 잇는다(약 100줄) |
| 작업대 상태 | Zustand | 스트림의 자료 조각을 받아 카드와 단계를 바꾼다 |
| 입체 매장 | react-three-fiber + drei, Kenney 에셋(4절) | 같은 앱 안에서 카드와 함께 그린다 |
| 차트 | SVG 직접 + d3-sankey | 구매 전환 경로 그림이 핵심이다 |
| 서버 | FastAPI(uv) | 기존 파이썬 스크립트와 CSV를 그대로 쓴다 |
| 전달 | AI SDK의 UI 메시지 스트림(SSE, 응답 머리에 `x-vercel-ai-ui-message-stream: v1`) | `useChat`이 그대로 받는다 |
| 자료 | CSV + DuckDB, 실험 기록은 SQLite | 지금 구조 그대로 |
| 모델 호출 | 한 곳에 모은 어댑터 | Claude API, OpenAI, `claude -p`, 재생(모델 없음)을 바꿔 끼운다 |

### 세 기준으로 본 이유

| 기준 | 판단 |
|---|---|
| 작업 편의 | 필요한 부품이 거의 다 있어 직접 만들 것이 적다. 명령줄(`astryx docs`, `component`, `search`)에서 부품의 속성과 예제를 바로 얻어, 구현 세션이 추측하지 않는다. 테마는 명령 몇 줄로 바꾼다 |
| 완성도 | 대화, 단계 표시줄, 카드가 한 벌이라 화면이 한 사람이 만든 것처럼 보인다. 색을 바꾸면 글자 대비와 호버 색이 함께 계산된다 |
| 연계 가능성 | 서버 안에서는 칠성이의 이벤트(말, 질문, 카드 상태 변경, 승인 대기)를 우리 형식으로 만들고, **맨 끝의 한 곳에서만** 내보내는 형식으로 바꾼다. 그 한 곳을 갈아 끼우면 AG-UI로도 내보낼 수 있다. 모델도 같은 방식으로 한 곳에서 바꾼다 |

### 견준 것과 고르지 않은 이유

| 후보 | 고르지 않은 이유 |
|---|---|
| 21st.dev Agent Elements + shadcn | 먼저 돌려 본 조합이고 동작했다. 그러나 대화 밖의 부품(단계 표시줄, 카드)과 모양을 우리가 잡아야 하고, 영어 문구와 대화 폭을 고치려면 받아 온 소스를 손봐야 한다. Astryx가 대화까지 한 벌로 되어 뺐다. **레퍼런스로는 계속 쓴다**(아래) |
| 당근 SEED | 참가자에게 익숙하고 버튼과 칩이 깔끔하다. 그러나 모바일 앱 중심이라 단계 표시줄, 카드, 대화가 없고, 브랜드 색을 바꾸는 공식 방법이 없어 토큰 10줄을 손으로 덮어써야 했다. 문서의 Vite 설정 예시대로 하면 화면이 뜨지 않는 함정도 있었다 |
| Vercel AI Elements | 질문 카드, 계획 카드, 모드 고르기가 없다 |
| AG-UI(통신 규약)를 처음부터 | 공유 상태와 중단·재개가 우리 작업대와 승인 지점에 잘 맞는다. 그러나 `useChat`과 이어 주는 공개 패키지를 찾지 못했다(`@ag-ui/vercel-ai-sdk`는 npm에 없다). 내보내는 한 곳을 바꿔 끼울 자리만 만든다 |
| A2UI | 에이전트가 화면 부품의 조합을 자료로 보내는 형식이다. 우리 부품은 일곱 가지뿐이고 입체 매장과 작업대 카드는 직접 그리므로 들이지 않는다. 연계를 말할 때의 확장 방향으로만 둔다 |
| Next.js | 서버가 파이썬이라 얻는 것이 없다 |

### 돌려 보고 확인한 것

같은 화면(여섯 단계 표시줄, 대화와 질문 카드, 작업대 숫자 카드, 버튼 셋, 진행 방식 고르기)을 Astryx와 SEED로 각각 만들었다. Opus 하위 에이전트가 12분쯤에 만들었고, 설계 세션이 두 앱을 다시 빌드하고 띄워 확인했다. 핵심 파일은 `app/reference/astryx-spike/`에 참고용으로 남겼다.

| | Astryx | SEED + Agent Elements |
|---|---|---|
| 설치와 빌드 | 통과. 설정 한 줄을 손봄 | 통과. 세 군데를 손봄 |
| 롯데 레드로 바꾸기 | 테마 편집기 명령 한 줄. 버튼 위 글자색과 강조 글자색을 대비에 맞춰 계산, 호버 색도 따라옴 | 색 토큰 10줄을 손으로 덮어씀. 눌린 색은 눈으로 고름 |
| Pretendard | 명령 한 줄 | 글꼴 변수를 다시 정의 |
| 대화와 질문 카드 | 자체 대화 부품과 RadioList, Button, Card의 조합. 스트림, 질문, 답, 다음 차례까지 동작 | Agent Elements 그대로. 변수 25개쯤을 이어 줌 |
| 직접 만든 것 | 작업대의 내역 줄 하나 | 단계 표시줄 전체, 작업대 카드, 내역 줄 |
| 묶음 크기(JS) | 1,280 kB | 1,610 kB |

### 만들 때 알아 둘 것

- **CSS의 순서**: `@layer reset, theme, base, astryx-base, astryx-theme, components, utilities;`를 `@import "tailwindcss"` 위에 둔다. 그다음 `@astryxdesign/core/reset.css`, `astryx.css`, 테마 CSS. `tailwind-theme.css`는 넣지 않는다.
- **pnpm 11**: Astryx 패키지의 설치 뒤 스크립트 때문에 빌드 앞의 점검이 실패한다. `pnpm-workspace.yaml`의 `allowBuilds`에 `@astryxdesign/core`와 `@astryxdesign/cli`를 `false`로 적는다.
- **테마**: `astryx experimental theme editor`로 만든다. 이름대로 실험 기능이라 판을 올리면 바뀔 수 있다. 만든 테마 폴더를 저장소에 두고 디자인 시스템의 근원으로 삼는다(3절).
- **선택 테두리**(`--shadow-inset-selected`)는 강조색을 바꿔도 파랑으로 남는다. 따로 지정한다.
- **보조 글씨색**(롯데 그레이)을 지정하면 어두운 모드의 대비 경고가 난다. 밝은 모드로 고정하고 넣는다.
- **버튼 모서리**는 기본이 16px이다. 알약 모양은 테마에서 바꾼다(`corners pill --on button`. 해 보지는 않았다).
- **좁은 작업대**에서 "칠성이에게 맡기기"가 말줄임으로 잘린다. 작업대의 폭이나 세그먼트의 배치를 먼저 정한다.
- **질문의 답**은 고른 선택지의 이름을 기획자의 말로 보내고 있다. 도구의 결과로 돌려보내는 방식(`addToolOutput`)으로 바꿀지 약속 파일에서 정한다.
- `astryx init`은 앱 폴더에 AGENTS.md와 GEMINI.md를 만든다. `app/CLAUDE.md`와 겹치지 않게 정리한다.
- `ai` 판을 올리면 스트림 형식이 바뀔 수 있다. 형식 문서는 `node_modules/ai/docs/04-ai-sdk-ui/50-stream-protocol.mdx`.
- 확인하지 않은 것: 어두운 모드, 좁은 화면, 키보드 조작, Astryx의 MCP 서버.

### 21st.dev의 쓰임 (레퍼런스)

21st.dev의 부품 모음과 MCP는 뼈대가 아니라 참고 자료다. 참가자가 MCP를 이 프로젝트에 등록했다(2026-11-19, 열쇠는 저장소에 없다).

1. Astryx에 있는 부품이면 그것을 쓴다.
2. 없으면 21st에서 구성과 모양을 보고 Astryx 부품을 조합해 만든다(질문 카드가 이렇게 만들어졌다).
3. 조합으로 안 되는 것만 소스를 가져오고, 색과 모서리를 Astryx 토큰으로 바꿔 입힌 뒤 견본 페이지에 올린다. 가져올 때 라이선스를 하나씩 확인한다.

폴더

```
app/web       화면 (src/chat: 대화와 질문 카드, src/workbench: 작업대 카드, themes/lotte: 테마)
app/server    서버 (scripts의 실험 코드를 불러 쓴다)
app/contract  서버와 화면 사이의 약속 (우리 도구의 이름과 입력 형식, 자료 조각의 형식)
app/tasks     작업 지시서
app/reference 시험 앱의 핵심 파일 (참고용)
app/CLAUDE.md 구현 세션이 읽는 짧은 안내
scripts, data 그대로
```

설계의 세 가지 원칙

1. **칠성이는 코드로 짠 상태 기계다.** 단계의 순서와 넘어가는 조건은 코드가 쥐고, 모델은 정해진 자리에서 정해진 형식(구조화된 출력)으로만 답한다. 모델을 바꿔도 흐름이 같다.
2. **약속을 가장 먼저 정한다.** 스트림 형식은 AI SDK의 것을 쓰고, 그 안에 실을 우리 도구(질문, 확인, 요약)와 자료 조각(작업대 카드, 단계, 진행 상황)의 이름과 형식을 정한다. 이것이 정해지면 화면과 서버를 따로 만들 수 있다.
3. **재생 방식을 먼저 만든다.** 대본 파일과 사전 측정 결과를 같은 스트림 형식으로 흘려보낸다. 모델 호출 없이 화면 전체를 개발하고, 현장에서 모델이 끊겨도 시연이 된다.

### 화면의 큰 모양 (참가자가 보여 준 레퍼런스를 따른다)

- **첫 화면**: 가운데에 작은 입체 편의점, 인사 한 줄과 "검토할 신제품을 알려 주세요" 한 줄, 추천 칩 세 개, 입력창과 진행 방식 버튼.
- **왼쪽 메뉴**(2026-11-19 참가자가 오픈서베이의 틀을 보고 두기로 함. 구성은 첫 화면을 만들어 보고 확정한다): 새 테스트, 최근 테스트(끝난 결과로 바로 가는 길이라 시연의 폴백도 된다), 매대, 소비자 패널, 신뢰도, 맨 아래 담당자. 모두 실제 자료가 있는 것만 둔다. 에이전트가 칠성이 하나이므로 레퍼런스의 에이전트 목록은 따르지 않는다. 대화가 시작되면 아이콘만 남기고 접는다.
- **대화가 시작되면**: 왼쪽이 대화, 오른쪽이 작업대로 갈라지고 위에 여섯 단계가 나타난다.

## 2. 작업 환경

비싼 모델은 설계와 검토만 하고, 코드는 아래 모델이 짠다. 참가자의 요금제는 Max이고 Claude Code로 작업한다.

| 역할 | 모델 | 방식 |
|---|---|---|
| 설계, 약속, 지시서, 검토 | Fable | 코드는 쓰지 않는다. 검증 명령의 통과 여부와 차이만 본다 |
| 구현 | Opus 5.5 | 큰 덩어리 하나에 지시서 한 장 |
| 단순 작업(문구 넣기, 부품 옮기기, 테스트 채우기) | Sonnet 5.5 | 구현 세션이 하위 작업으로 넘기거나 따로 돌린다 |

가벼운 하네스 (모델을 올려도 유지한다)

- **지시서**: `app/tasks/NN-이름.md`. 목표, 지켜야 할 약속 파일, 건드리는 폴더, 끝났다는 기준(통과할 명령)만 적는다. 파일 단위로 쪼개 적지 않는다.
- **짧은 안내**: 구현 세션은 `app/CLAUDE.md`, 지시서, 약속 파일만 읽고 시작한다. 기획 문서 전체를 읽히지 않는다.
- **검증은 명령으로**: 타입 검사, 빌드, 서버 테스트가 통과해야 끝이다.
- **모델 호출 비용**: 개발 중에는 재생 방식만 쓴다. 실제 모델은 `claude -p`로 부르고 같은 요청의 결과는 저장해 다시 부르지 않는다.

워크트리로 넘어가는 때

- 처음(약속과 뼈대)은 워크트리 없이 한 세션씩 차례로 한다. 여기서 폴더 구조가 생기므로 나누면 서로 기다린다.
- **뼈대가 main에 들어가고, 건드리는 폴더가 겹치지 않는 지시서가 둘 이상 준비되면** 설계 세션이 참가자에게 "이제 나눠서 돌리자"고 먼저 제안한다. 그때 Orca로 옮겨 이 세션을 이어 가고, 워크트리는 많아야 둘이나 셋(화면, 서버, 입체 매장)이다.
- 한 번에 하나만 돌릴 때는 워크트리를 만들지 않는다.

## 3. 디자인 시스템

목적: 화면 어디를 봐도 한 사람이 만든 것처럼 보이게 하고, AI가 만든 티가 나는 모양을 막는다. 구현 세션이 색과 간격을 그때그때 정하지 못하게 하는 것이 핵심이다.

### 방향 (2026-11-18 참가자가 레퍼런스를 보여 주어 조정)

**전체 틀은 부드럽게, 숫자 카드만 가격표와 영수증처럼.** 대화, 입력창, 칩, 버튼은 레퍼런스처럼 흰 바탕, 둥근 모서리, 알약 모양, 옅은 회색 면으로 한다. 강조색은 롯데 레드 하나다(Astryx 테마의 강조색). 아래의 "가격표와 영수증" 규칙은 화면 전체가 아니라 **작업대에서 숫자를 보여 주는 카드**에만 쓰고, 모서리와 선은 틀에 맞게 부드럽게 한다. 아래 표에서 버튼과 단계 표시줄의 색 규칙(강조는 빨강 하나)은 그대로 쓴다.

### 숫자 카드의 규칙: 가격표와 영수증

한 문장으로: **편의점의 가격표처럼 숫자가 주인공이고, 영수증처럼 줄을 맞춘 내역이 그 아래에 붙는다. 색은 롯데 CI의 색만 쓰고 강조는 빨강 하나다.**

화면에서 실제로 달라지는 것

| 무엇 | 이렇게 한다 | 가져온 곳 |
|---|---|---|
| 핵심 숫자 | 카드마다 하나를 아주 크게(선택률 18%), 옆에 작은 글씨로 뜻(300명 중 54명) | 가격표의 큰 가격과 작은 단위 |
| 내역 | 이름은 왼쪽, 숫자는 오른쪽, 사이는 점선, 맨 아래 굵은 선과 합계 | 영수증 |
| 카드 | 흰 종이색 바탕, 위에 굵은 검은 선, 나머지는 가는 선. 그림자 없음, 모서리는 거의 각지게 | 매대의 가격표 띠 |
| 주석 | 카드 맨 아래 점선 밑에 작은 글씨(결과 신뢰도, 가상 소비자의 답) | 영수증 아래의 안내문 |
| 버튼 | 주 버튼 하나만 빨강으로 채우고 나머지는 검은 테두리 | |
| 단계 표시줄 | 지금 단계만 빨강으로 채움 | |

| LOTTE Red | R218 G41 B28 (#DA291C), PANTONE 485c | 강조 하나: 주 버튼, 지금 단계, 핵심 숫자, 우리 신제품 |
| LOTTE Black | #000000 | 글씨, 굵은 선 |

- CI 안내는 빨강을 주색으로, 금색과 은색을 제한적으로 쓰라고 한다. 우리도 빨강은 화면에 한두 곳만 쓴다.
- 롯데의 심볼마크와 로고는 화면에 넣지 않는다(쓰는 규정이 따로 있다). 색만 따른다.
- 글꼴: Pretendard 하나. 숫자는 폭이 같은 숫자(tabular)로 쓴다.
- 움직임: 뜻이 있을 때만(카드가 펼쳐짐, 숫자가 쌓임).
- 칠성이 캐릭터(2026-11-20 참가자가 고름): 통통한 캔 모양에 눈 두 개, 초록. [open-bot-avatar](https://github.com/DominikScholz/open-bot-avatar)(MIT)로 그린다. 윤곽선 하나와 눈의 위치로 정의하고, 눈을 깜빡이며 마우스를 따라 보고, 상태 세 가지(기본, 생각 중, 기쁨)가 있다. 초록은 칠성이에게만 쓴다(값은 우리가 고른 것이고 칠성사이다의 공식 색이 아니다). 칠성사이다의 로고와 별 무늬는 따오지 않는다.
- 아이콘: Astryx의 아이콘 한 벌. 이모지를 아이콘으로 쓰지 않는다.

### 하지 않는 것

- 보라색 그라데이션, 반투명 유리 효과, 빛나는 테두리
- 모든 것을 둥근 카드와 그림자에 넣기
- 가운데 정렬한 큰 제목과 부제
- 이모지, 반짝이 아이콘, "AI" 배지
- 뜻 없는 색 구분(카드마다 다른 색)
- 디자인 시스템의 기본 테마 그대로(강조색과 글꼴을 바꾸지 않은 상태)

### 층

| 층 | 무엇 | 약속 |
|---|---|---|
| 테마 | Astryx 테마 `themes/lotte`: 강조색, 글꼴, 모서리, 밝은 모드 고정. 테마 편집기로 만든다 | 색과 크기의 값은 여기에만 있다 |
| 기본 부품 | Astryx의 부품(Button, Card, Stepper, SegmentedControl, Table, Badge, Skeleton, Toast 등) | 화면 코드는 색과 크기를 직접 적지 않는다. Tailwind는 배치와 간격에만 쓴다 |
| 대화 부품 | Astryx의 대화 부품(ChatLayout, ChatMessageList, ChatMessage, ChatComposer, ChatToolCalls) 위에 우리 것: 질문 카드, 추천 칩, 버튼 묶음, 숫자 고르기, 확인 카드, 요약 카드 | [ux-writing.md](ux-writing.md) 8절의 부품과 하나씩 맞는다 |
| 작업대 카드 | 기획 브리프, 컨셉 보드, 제품별 선택률, 구매 전환 경로, 개선안, 결과 보고서 | 카드마다 기다림, 비어 있음, 실패의 모습을 함께 만든다 |

- **견본 페이지**(`/design`): 모든 부품과 카드를 상태별로 한 화면에 늘어놓는다. 구현 세션은 새 화면을 만들기 전에 여기 있는 부품을 쓰고, 없으면 여기에 먼저 추가한다.
- **문구는 한 파일**(`copy.ts`): 화면의 이름과 버튼 이름을 모은다. 현장에서 받은 용어로 바꿀 때 여기만 고친다.
- Astryx에 없는 부품은 1절 "21st.dev의 쓰임"의 순서를 따른다.
